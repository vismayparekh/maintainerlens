## Classifier holdout and release

The new holdout has 32 issues with eight examples per category. It uses
CPython, Flask, and Streamlit, all outside the models' training sources and
previous category benchmarks. GitHub labels provided expected categories
and documentation maps to Other. Streamlit supplies all Question examples
and CPython supplies all Feature request examples. This couples those
classes to repository-specific language. The set needs independent labels.

| Method | Macro F1 | Accuracy | Bug recall |
| --- | ---: | ---: | ---: |
| Live text rules | 77.9% | 25 / 32 | 7 / 8 |
| Classifier v1, 594 samples | 68.4% | 22 / 32 | 4 / 8 |
| Classifier v2, 610 samples | 75.1% | 24 / 32 | 6 / 8 |
| Classifier v3, 638 samples | 68.0% | 22 / 32 | 5 / 8 |

V2 is the strongest trained candidate on this set. Results vary on the
earlier 24-issue bug/question test, where v1 led. The live demo uses the rule
baseline. I downloaded and loaded the published v2 artifact anonymously.

## Human review

Argilla has six PR briefs and 32 blind issue-classification records pending.
Both queues had zero independent submissions when checked. The local reply
pilot database has three recorded trials across two issues. The two manual
entries have a median of 7.28 seconds. The one assisted entry took 65.77
seconds and was accepted unchanged. An independent reviewer has yet to check
these replies for factual errors. The existing trials did not follow the
counterbalanced assignment, so they are exploratory observations. A blinded
sheet for these entries is ready in the ignored local pilot directory.

To finish the human evaluation, use one reviewer per sequence A and B and a
separate blinded quality reviewer. Use the existing reply-pilot commands to
export, score, and report case-matched timing and acceptance. The issue
classifier retraining input is the Argilla consensus CSV once two reviewers
have submitted matching labels.

## LoRA PR-review pilot

SmolLM2-135M-Instruct was trained locally for three epochs on 24 synthetic
PR metadata examples. Rank-8 LoRA targeted the query and value projections.
Training updated 460,800 parameters and took 167 seconds on this CPU.
The base and adapted models received the six frozen scikit-learn and pandas
PR inputs used by the current DeepSeek generator. The current generator's
baseline uses the saved provider run with JSON response mode.

| Model | Outputs meeting the app schema | Median request time |
| --- | ---: | ---: |
| SmolLM2 base, local CPU | 0 / 6 | 7.52 s |
| SmolLM2 with LoRA, local CPU | 0 / 6 | 8.27 s |
| Current DeepSeek generator, earlier hosted inference run | 6 / 6 | 7.38 s |

The adapted model generally began a JSON object and reflected parts of the
PR description. It still produced incomplete JSON, repetitive text, or
invented fields. The outputs could not be graded as usable briefs with the
production rubric. Inference times come from different hardware and runtime
conditions. The current generator stays in production. Use independently
corrected examples and a larger holdout before scheduling retraining.
[SmolLM2 model card](https://huggingface.co/HuggingFaceTB/SmolLM2-135M-Instruct)
